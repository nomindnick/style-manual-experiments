# LS-CAP-02 candidate labeling

Each `candidates.{fixture}.json` file is a flat list of candidate occurrences
of an LS-CAP-02 trigger phrase (district / board / city / county / agency /
authority and the common multi-word forms) found in body-prose paragraphs of
the corresponding fixture.

## Labels

Fill in each row's `label` field with one of:

- **`must_capitalize`** — the form should be capitalized in this position; the
  rule should flag if it is currently lowercase.
- **`must_lowercase`** — the form should be lowercase; the rule should flag if
  it is currently capitalized.
- **`do_not_flag`** — the manual is silent, both forms are acceptable, or the
  rule does not apply (case names in citations, quoted statutory text, etc.).

`notes` is optional. Use it when the call was non-obvious or when you want to
preserve reasoning for future reference (e.g., "case name in cite", "either
form OK because no defined-term context").

## Reading a row

- `current_form` — the trigger phrase as it appears in the draft, case
  preserved. The label is your judgment about what the form **should** be in
  this position, independent of how it currently appears.
- `paragraph_text` — the full paragraph containing the candidate.
- `prior_paragraph_text` — the immediately preceding paragraph; useful for
  checking whether a defined-term reference (e.g., `District` defined as a
  party substitute) was set up earlier.

## Common cases

- A bare `District` / `Board` referring to the named defendant client → almost
  always `must_capitalize`.
- `school district` / `the district` used in an abstract or statutory sense
  ("a California school district may...") → `must_lowercase`.
- A trigger word inside a case name (e.g., `Los Angeles County Board of
  Education v. Smith`) → `do_not_flag`; the case name is reproduced verbatim
  and is outside the rule's scope.
- Trigger word inside quoted statutory or contract text → `do_not_flag`.
- Trigger word inside a section heading → `do_not_flag` (heading-case
  conventions are independent of LS-CAP-02).
- Trigger word in a **compound modifier** or **function-descriptor** position:
  `board-approved`, `school-district contracts`, `school-district public
  works`, `board approval`, `board action`, `the governing board`,
  `board-of-trustees [adj]` → `do_not_flag`. The manual is silent on compound
  modifiers; LS practice is to write them lowercase, but the rule abstains
  rather than firing in either direction. This applies even when the
  surrounding sentence is unambiguously about the named District (e.g., "the
  District obtained board approval" — `board` here is `do_not_flag`).

## Scope of the v0 corpus

For Phase 1 Rule 3, label only `candidates.kitchen-sink.json` first.
Kitchen-sink contains the most violation variety and all seeded LS-CAP-02
violation directions (false-lowercase + false-capitalize). The other two
fixtures' candidate files are generated by the same script and can be labeled
later if the eval signal is thin.
